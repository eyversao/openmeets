Nube

La versión en la nube vive en openmeets.web.app. No hay servidor: el navegador habla directo con Firestore, y las reglas de la base de datos son la seguridad. Sirve para crear meets y compartirlos por internet. La mesa de un gimnasio sigue funcionando sin internet con la app local.

Cómo funciona

  • Firebase Hosting sirve la web (el mismo código de web/, empaquetado).
  • Firestore guarda los meets, los atletas, el estado en vivo y los votos. El tiempo real sale de las escuchas de Firestore, no de un canal SSE.
  • Auth con Google identifica a quien organiza. Cada cuenta solo puede dirigir los meets que creó, hasta 50. Jueces y público no necesitan cuenta.
  • El meet puede ser público o privado. La cuenta dueña nunca se muestra en las páginas públicas.
  • El código de jueces vive en un documento aparte (meets/<id>/privado/datos) que solo lee el dueño. Los jueces votan con ese código y las reglas lo comprueban.

Qué cambia respecto a la app local

  • Hay cuentas y no hay PIN de organizador.
  • Las funciones que dependen de una carpeta en tu equipo (perfiles de atletas entre meets, récords del servidor, modo federación) no están. La app lo avisa y te manda a la versión de tu red local.
  • Sin internet no hay nube. Para competir sin conexión usa la app local.

Reglas de Firestore

Están en firestore.rules y definen qué puede leer y escribir cada quien: lectura pública solo de meets públicos, escritura solo del dueño, validación de campos y tamaños, y votos de jueces con código. Se prueban contra el emulador:

npm run reglas

Hace falta Java (el emulador de Firestore lo usa) y descarga firebase-tools la primera vez.

Publicar tu propia versión

Puedes montar la nube con tu propio proyecto de Firebase. Los pasos:

  1. En la consola de Firebase crea un proyecto. Activa Firestore (modo producción), Authentication con el proveedor de Google y añade una app web para obtener su configuración.
  2. En Hosting crea un sitio. Ajusta .firebaserc con tu proyecto (default), el proyecto donde está el sitio (sitio) y, en targets, el nombre del sitio. En Authentication → Configuración → Dominios autorizados añade el dominio del sitio.
  3. Guarda la configuración web de Firebase en un JSON (apiKey, projectId, etc.) fuera del repositorio y apunta a él con la variable OPENMEETS_FIREBASE_CONFIG. Esa clave es pública, pero no se versiona.
  4. Restringe la clave web en Google Cloud (sitios y APIs permitidos).
  5. Instala las dependencias y publica:
npm install
npm run nube:desplegar

npm run nube:build prepara la carpeta publico/: copia web/, la empaqueta con esbuild y escribe publico/nube.json con tu configuración. La app detecta la nube porque ese archivo existe. nube:desplegar hace lo anterior y publica las reglas de Firestore y el sitio con firebase-tools. Antes inicia sesión con npx firebase-tools login.

Las reglas van antes que el sitio

El código de la web depende de ellas. El script ya las despliega primero; si publicas a mano, hazlo en ese orden.

Copia de seguridad

Desde un meet puedes descargar su copia completa (export.json) y restaurarla después. Es el mismo formato que usa la app local, así que un meet puede pasar de una a otra.
