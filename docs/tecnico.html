Técnico

Cómo está hecho OpenMeets, su API completa y cómo se construye.

Arquitectura

La misma web corre de dos formas: una app local en la red del gimnasio y una versión en la nube (ver Nube).

OpenMeets/
  nativo/     servidor en Rust (openmeets.exe, con la web embebida)
  instalador/ instalador de Windows en Rust (OpenMeets-Setup.exe)
  servidor/   servidor Node para desarrollo y base de las pruebas: openmeets.mjs (arranque y consola)
              almacen.mjs · api.mjs · tiempo-real.mjs · acceso.mjs · estatico.mjs · calculo.mjs
              inscripciones.mjs · records.mjs · federacion.mjs · openpowerlifting.mjs
  web/        index.html · sw.js · css/ · js/ (app.js, api.js, canal.js, ui.js, i18n.js,
              nucleo/ módulos puros, vistas/, nube/ Firestore) · fuentes/ · iconos/
  marca/      logos SVG, manual, interfaz del instalador
  docs/       esta documentación
  mandos/     sketches Arduino/ESP32 y su guía
  scripts/    nube-build.mjs · sw-lista.mjs · precarga.mjs
  pruebas/    *.test.mjs y correr.mjs
  firestore.rules · firebase.json · .firebaserc   la nube
  • App local de Windows: openmeets.exe, escrito en Rust, lleva la web dentro. Es un solo archivo y habla el mismo contrato que el servidor Node. Se instala con OpenMeets-Setup.exe, otro programa en Rust con su propia ventana.
  • Servidor Node: solo la biblioteca estándar de Node 20 o superior, sin dependencias de npm al ejecutar. Sirve para desarrollar en cualquier sistema (npm start) y es contra lo que se prueba el servidor Rust. Escucha en 0.0.0.0, puerto 5050 por defecto.
  • Web: módulos ES servidos tal cual, sin paso de compilación en local. Rutas limpias (/organizar, /juez/<id>), nunca #. Cualquier ruta que no sea un archivo devuelve index.html. Solo la versión en la nube se empaqueta (esbuild).
  • Tiempo real (local): Server-Sent Events por /api/meets/:id/canal, con un ping cada 15 s. No hay límite de duración de petición: el canal vive horas. En la nube lo sustituyen las escuchas de Firestore.
  • Núcleo: web/js/nucleo/ son funciones puras (reloj, luces, votos, puntos, CSV, discos, federaciones). Corren igual en el navegador y en Node, y por eso tienen pruebas.
  • Almacenamiento: en local, un archivo JSON por meet detrás de almacen.mjs. En la nube, Firestore.

Roles y seguridad

  • Organizador: toda petición desde el propio equipo (loopback) o con la cookie de sesión que se obtiene con el PIN. En la nube, la cuenta de Google dueña del meet.
  • Juez: manda votos y presencia por POST .../canal con el código de jueces del meet.
  • Público: lee lo público y puede mandar aplausos.
  • Una petición que cambia datos con un Origin distinto del Host se rechaza (403), para que otra página no use tu servidor.
  • Cuerpos JSON obligatorios (415 si no); límites: 256 KB normal, 64 KB canal, 1 MB lote de atletas, 8 MB importar.
  • El código de jueces y el PIN se comparan en tiempo constante. El bloque privado del meet nunca sale a quien no es organizador.
  • La app local está pensada para una red local de confianza. No la expongas directamente a internet; para eso está la nube.

API (app local)

Todo es JSON. Los errores devuelven {ok: false, error: "texto en español"} con su código HTTP. «Organizador» se explica arriba; sin permiso responde 403. En la nube la web llama a las mismas rutas, pero se resuelven en el navegador contra Firestore (web/js/nube/rutas.js).

MétodoRutaQuiénQué hace
GET/api/infoPúblicoVersión, puerto, IPs de la red local y si quien pregunta es organizador. Respuesta: {app, version, puerto, ips, organizador}.
POST/api/sesionPúblicoCuerpo {pin}. Abre sesión de organizador y pone la cookie om_sesion (HttpOnly, SameSite=Strict). 5 intentos por minuto por IP; 401 si el PIN es incorrecto, 429 si te pasas.
DELETE/api/sesionCualquieraCierra la sesión y borra la cookie.
GET/api/pinOrganizadorDevuelve {ok, pin}.
PUT/api/pinOrganizadorCuerpo {pin} de 6 dígitos (o vacío para uno aleatorio). Cierra todas las sesiones.
GET/api/meetsPúblicoLista pública ordenada por fecha descendente: [{id, nombre, fecha, fechaFin, ciudad, pais, federacion, estado, atletas, plataformas, publico}]. Con ?todas=1 el organizador incluye los no públicos.
POST/api/meetsOrganizadorCrea un meet (cuerpo con los campos del meet; nombre obligatorio). 201 con el meet, que incluye el código de jueces.
POST/api/meets/importarOrganizadorRestaura una copia (export.json). ?reemplazar=1 sobrescribe un meet existente (el anterior queda en .bak). Hasta 8 MB.
GET/api/meets/:idPúblico*El meet con su estado. Sin el bloque privado salvo para el organizador. *Un meet no público devuelve 404 a quien no es organizador.
PATCH/api/meets/:idOrganizadorCambia campos del meet (no atletas ni vivo). Acepta privado.codigoJuez o codigoJuez. Emite meet-cambio por el canal.
DELETE/api/meets/:idOrganizadorMueve el archivo a <datos>/papelera.
POST/api/meets/:id/atletasOrganizadorLote {atletas: [...]} (hasta 1000, 1 MB). Crea o reemplaza por id; sin id se genera uno. Respuesta {ok, atletas}.
PUT/api/meets/:id/atletas/:aidOrganizadorCrea o actualiza un atleta. Anota en la actividad cada resultado nuevo. Emite atleta.
DELETE/api/meets/:id/atletas/:aidOrganizadorQuita al atleta y sus aplausos. Emite atleta con eliminado: true.
GET/api/meets/:id/resultados.csvPúblico*Resultados en CSV (UTF-8 con BOM). Las celdas que parecen fórmulas de Excel llevan un apóstrofo delante.
GET/api/meets/:id/export.jsonOrganizadorCopia completa del meet para restaurar con /api/meets/importar.
POST/api/meets/:id/aplausoPúblico*Cuerpo {aid}. Suma un aplauso; máximo 1 cada 10 s por IP, meet y atleta (429). Respuesta {ok, n}.
GET/api/meets/:id/canalPúblico*Flujo de eventos (SSE). Ver abajo. Quien es organizador recibe también los eventos privados.
POST/api/meets/:id/canalSegún el tipoPublica un mensaje: ver tipos abajo. Hasta 64 KB.

Eventos del canal (GET)

Cada evento llega como data: {"tipo": ..., ...}. Al conectar, el servidor manda el meet entero y el estado en vivo de cada tarima.

TipoDatosPara quién
meet{meet} completo (con estado, sin privado si no es organizador)Todos, al conectar
vivo{plataforma, datos}: atleta actual, siguientes, reloj, luces…Todos
atleta{atleta}, o {id, eliminado: true}Todos
meet-cambio{campos} modificados; {eliminado: true} si se borróTodos
aplauso{aid, n}Todos
voto{voto} de un juezSolo organizador
presencia{datos}: posición, batería, dispositivo, nombreSolo organizador
limpiar{plataforma}Solo organizador

Mensajes del canal (POST)

CuerpoQuiénEfecto
{tipo: "vivo", plataforma, datos}OrganizadorGuarda y difunde el estado en vivo. Si datos.version es menor que la guardada, se ignora (ignorado: true). Borra los votos del turno anterior.
{tipo: "limpiar", plataforma}OrganizadorBorra los votos de esa tarima.
{tipo: "voto", voto}Juez con códigovoto lleva codigo, plataforma, pos (izq, cen, der), voto (blanca o roja), tarjetas, turno, via, dispositivo, secreto. El primer voto de cada juez por turno cuenta; los repetidos devuelven repetido: true.
{tipo: "presencia", datos}Juez con códigoLatido con codigo, plataforma, pos, bateria, nombre, huella. Guarda al juez como conocido (hasta 50 por meet).

Modelo de datos

Cada meet es un archivo JSON. Resumen de sus campos:

meet = { id, nombre, fecha, fechaFin, sede, ciudad, pais, organizador, descripcion, stream,
  federacion, modo: 'IPF'|'otra', aprobacion: 'abierta'|'mesa'|'codigo', unidades: 'kg',
  formula: 'GL'|'DOTS'|'Wilks'|'IPF', barra, barraSentadilla?, collar,
  discos: [{kg, pares, color}], relojes: [60, 180], pararAlVotar, plataformas: ['Tarima 1'],
  publico, cerrado, hud, atletas: [atleta], vivo: { [plataforma]: vivo },
  aplausos: { [aid]: n }, actividad: [{ts, texto}],      // últimos 500
  privado: { codigoJuez, juecesConocidos: { [huella]: {pos, nombre, ts} } },
  creado, actualizado }

atleta = { id, nombre, sexo: 'M'|'F', nacimiento?, club, division, equipamiento: 'raw'|'equipado',
  peso, clase, plataforma, sesion, grupo, lote, rack: {S, B},
  intentos: { S: [i, i, i], B: [i, i, i], D: [i, i, i] } }

i = { kg, r: 1 | -1 | null, rec, alFinal, cambios?, historial?: [{ts, de, a, motivo}] }

El estado (en-vivo, programada, terminada) no se guarda: se calcula. Es en vivo si alguna tarima tiene atleta actual y el meet no está cerrado; es terminada si está cerrado o su fecha (de fin) ya pasó.

Carpeta de datos y copias

Por defecto: %LOCALAPPDATA%\OpenMeets\datos en Windows y ~/.openmeets en Mac y Linux. Cámbiala con --datos <carpeta>. El instalador y el desinstalador no la tocan, salvo que pidas borrarla al desinstalar.

RutaQué hay
meets/<id>.jsonUn meet. Se escribe atómicamente (archivo temporal y renombrado), agrupando cambios cada 300 ms.
meets/<id>.json.bakLa versión anterior de ese meet.
papelera/Meets eliminados (<id>-<fecha>.json). Para recuperar uno, cópialo a meets/ o impórtalo.
config.jsonEl PIN de organizador.
openmeets.logRegistro de arranque y errores (rota a 1 MB).

Copias de seguridad: copia la carpeta meets/ a un USB al terminar cada sesión, o descarga /api/meets/<id>/export.json (desde el equipo de la mesa) y restáurala con /api/meets/importar. Con el servidor cerrado, puedes copiar la carpeta entera sin riesgo.

Funcionamiento sin conexión

web/sw.js es un service worker. En la primera carga guarda la web (HTML, CSS, JS, fuentes e íconos) en el navegador. Después abre aunque el servidor no responda un momento. Los estáticos salen de la caché y se refrescan en segundo plano; la navegación va a la red y, si falla, usa el index.html guardado. Las rutas /api/*, el canal SSE y cualquier petición que no sea GET nunca pasan por la caché.

La lista de archivos y la versión de caché las escribe node scripts/sw-lista.mjs. Si añades archivos a web/, vuelve a correrlo (la prueba de precarga avisa si se te olvida). Los archivos no listados se guardan igualmente la primera vez que se piden.

Para desarrolladores

Necesitas Node.js 20 o superior. Para la nube y las pruebas de reglas, npm install (esbuild y firebase son dependencias de desarrollo).

Arrancar

npm start          # servidor Node en http://localhost:5050/
npm run nativo     # compila el servidor Rust: nativo/target/release/openmeets.exe

Los dos aceptan --puerto, --datos y --sin-navegador; el de Rust también --web <carpeta>, para servir la web desde disco mientras desarrollas. start.bat usa el exe de Rust si ya lo compilaste y, si no, Node. Para npm run nativo hace falta Rust estable (cargo).

Pruebas

npm test                          # todas, contra el servidor Node
OPENMEETS_SERVIDOR=rust npm test  # las de API por HTTP contra el binario de Rust
npm run reglas                    # reglas de Firestore en el emulador (necesita Java)
node pruebas/correr.mjs jueces    # solo los archivos que contengan «jueces»

Cada archivo pruebas/*.test.mjs corre en su propio proceso de Node, sin navegador. Cubren el núcleo (reloj, luces, votos, puntos, CSV, LiftingCast, mandos), el servidor (API, almacén, acceso, tiempo real, archivos estáticos) y la versión en la nube con un Firestore falso en memoria. Para probar el binario de Rust, compílalo antes con npm run nativo. Dentro de nativo/ e instalador/, cargo test corre sus pruebas unitarias.

Compilar el instalador

npm run nativo
cd instalador
OPENMEETS_PAYLOAD=../nativo/target/release/openmeets.exe cargo build --release

Sale instalador/target/release/openmeets-setup.exe; cópialo a dist/OpenMeets-Setup.exe. El instalador lleva dentro el exe comprimido y la interfaz de marca/instalador/ui/. No pide administrador, instala en %LOCALAPPDATA%\Programs\OpenMeets, crea los accesos directos y la entrada de «Aplicaciones» de Windows. También admite /S (silencioso), --carpeta, --sin-escritorio y --desinstalar (con --borrar-datos). El detalle está en instalador/README.md. dist/ no se sube a git. Nada va firmado, por eso SmartScreen avisa.

Publicar la nube

npm run nube:desplegar

Construye publico/ y publica las reglas de Firestore y el sitio de Hosting. Los pasos para usar tu propio proyecto de Firebase están en Nube.
